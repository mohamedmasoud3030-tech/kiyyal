## Template adoption constraints

1. A template is not a permission layer. Each route’s server data shape and route guard must be correct before composition.
2. Component state, empty/error/offline/loading boundaries must be implemented at the template seam so every route gets them consistently.
3. Templates cannot introduce horizontal overflow at 320px or an unlimited form line width at wide desktop.
4. A custom `BuyerBrowseTemplate` and `RegradeTemplate` are justified exceptions because their primary tasks differ materially from general management/query patterns; they still use canonical primitives.
5. No template/component may be marked `VERIFIED COMPLETE` until it has a rendered mobile, tablet, laptop and wide-desktop sample with keyboard, RTL, long content and state evidence.
