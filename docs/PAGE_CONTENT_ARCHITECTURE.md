# Page Content Architecture

**Decision status:** the architecture remains binding. Its implemented subset is `IMPLEMENTED BUT NOT VERIFIED` until a configured authenticated browser journey is exercised; safety/route/build evidence is recorded in the current checkpoint below. Planned rows remain requirements, not claims that the full product exists.
**Evidence base:** baseline route audit, `docs/PRD.md` §§2–6 and §9.3, API/permission contracts, schema, real-PostgreSQL tests, and the 2026-09-15 build/test run.

## Global hierarchy rules

1. The next operational decision comes before summaries. A scale operator opens directly into an action, not a dashboard.
2. Weight, price unit and total remain visible while entering a financial movement. A line’s unit is always adjacent to its price and is visibly marked when overridden.
3. Owner-only money/cost/profit data is not merely visually hidden: it must be omitted from the server response for operators.
4. Every irreversible/financial outcome has a named Arabic verb, a concise consequence and a valid recovery path. There is no generic “OK”.
5. Do not create speculative charts, KPI cards or activity feeds. A summary appears only where it answers the owner’s immediate decision question.
6. Route data comes from scoped API contracts. `yard_id`, totals, cost, role and authorization never come from browser input.

## Acceptance across every page

- `lang="ar" dir="rtl"`; logical CSS only; Arabic labels and Arabic screen-reader names.
- 48×48px minimum touch targets, visible focus, semantic headings, correct labels/errors, and no icon-only money/destructive action.
- Text, long party/material names, multi-line notes and mixed Arabic/Western numerals wrap or truncate with a discoverable full value—never overlap or change financial values.
- Initial, empty, no-result, error, offline, permission, disabled, success, pending and expired-session states are part of the route implementation and test plan, not follow-up polish.
- Every route is validated at mobile, tablet, laptop and wide desktop widths, 200% zoom, keyboard-only and screen-reader landmark/navigation paths before it may be marked `VERIFIED COMPLETE`.
