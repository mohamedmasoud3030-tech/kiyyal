# Form Component Standard

**Decision status:** low-level primitives and a limited real form subset are `IMPLEMENTED BUT NOT VERIFIED`; every unlisted behaviour remains `NOT STARTED` target standard.
**Source of truth:** PRD FR-1–FR-16, edge cases E1–E35, API Contract §1, Frontend Rules, PWA Rules and existing server-domain services.

## Non-negotiable form contract

1. **One raw-string boundary.** Numeric controls hold raw Arabic-Indic or Western decimal strings. A normalization adapter converts acceptable input to canonical decimal strings; no UI component calls `Number`, `parseFloat`, or performs money/weight arithmetic.
2. **One source for preview arithmetic.** Fast forms need a pre-save weight/total preview. Per ADR-0013, the implementation must call the existing shared pure domain calculation module through a non-React preview adapter; it is display-only and is recomputed authoritatively by the server on save. No formula may be reimplemented in JSX, form reducers or API handlers.
3. **Server authority.** Mutation requests contain only user-entered fields and `Idempotency-Key`; net weight, totals, per-kg price, cost, profit, balances, `yard_id` and role are never trusted from the form. Server success response replaces the local preview.
4. **One submit state.** A form has one submission controller that prevents duplicate taps/Enter submits, preserves the same idempotency key through retry and disables only the submit action—not cancellation or readable context—while in flight.
5. **Recoverable failure preserves work.** Field values, selected material/party, active line and draft state remain after validation, conflict, timeout or retryable network failure. Focus goes to a validation summary then the first invalid field after explicit submit.
6. **Drafts are scoped and safe.** In-progress transaction/regrade/setup drafts persist locally under the authenticated yard/user scope. PIN/password/session token never persist. Operator caches/outbox never include cost, profit or cash totals. Clear all cache/drafts on logout, device switch or yard change according to PWA Rules.
7. **No fake completion.** A locally held request is labelled as retrying/safe on this device and is never shown as posted, numbered, revenue, profit or stock until server confirmation.
8. **Transactional safeguards are explicit.** Reversal, void, close, stock adjustment and relation removal name the exact action/effect, require the contract’s reason fields and cannot submit through Escape/overlay click.
9. **Accessible feedback.** Every field has a visible Arabic label, optional hint/unit, programmatic error association and a target size suitable for field use. Error colour is supplementary. Required/optional status is conveyed in text.
10. **Actions respond to viewport.** On phone, primary save/review remains fixed above the virtual keyboard and safe area; on desktop, actions follow the natural Tab sequence and `Enter` adds a transaction/regrade line only when focus is in a valid line field.

## Shared form anatomy

| Part | Standard |
|---|---|
| Header | Page/sheet title, one-sentence outcome, optional draft/sync state. A destructive action uses a separate confirmation title, not the normal form header. |
| Groups | Use named `<fieldset>`/legend or semantic section per decision group. Do not create a card per field. The order follows the real-world sequence, not schema order. |
| Labels and hints | Label is direct and concise; hint describes format, consequence or unit only where needed. Price label always names its active unit. |
| Required vs optional | Required when the server cannot safely infer/determine it. Mark optional fields explicitly only where the absence is otherwise ambiguous. Never make informal-party details mandatory beyond name-or-phone. |
| Defaults | Default the last permitted/remembered weighing mode, active material unit/reference price, cash-in-full and current business date. Defaults remain visible/editable; never silently preselect a party or reason. |
| Validation | Validate required/format/cross-field conditions early for convenience. Server validates every condition again and returns Arabic contract errors. Cross-line requirements show both a summary and the relevant field/group message. |
| Success | Confirm result with actual status/number from server, then offer receipt/detail/next record. Do not clear a financial form before server success. |
| Cancellation | Prompt only when a materially changed draft would be lost. “Cancel” discards local draft only after confirmation and never reverses a saved transaction. |
| Timeout/offline | Preserve draft/request and idempotency key, show local-safe retry state; retry automatically and manually. If the session expires, protect non-sensitive draft then require re-authentication. |
| Unsaved changes | Browser/route navigation guard only after user modifications. On successful save, clear draft atomically after server acknowledgement. |
| Autocomplete/input mode | Phone/name fields use appropriate `autocomplete`; PIN/password use secure settings; numeric money/weight uses `inputMode="decimal"`; phone uses `inputMode="tel"`; notes use normal text keyboard. |

## Preview, autosave and idempotency decision

| Situation | Required behaviour |
|---|---|
| User changes a transaction line | The form preview adapter uses the shared decimal/domain module to show net kg/line total immediately. It is labelled as a pre-save preview; no client value is authoritative or sent as a trusted total. |
| User changes material unit | The entered price is **not converted**. The unit control, visible price label, preview, summary and final server receipt all reflect the selected unit. An override marker appears when it differs from material default. |
| User begins a form | Store a scoped local draft after meaningful input, throttled and without PIN/token/forbidden operator fields. Restore only after an explicit “continue draft” acknowledgement if it could surprise the user. |
| User submits | Generate/store one UUID idempotency key for that intent. Disable duplicate submit; send raw input; server recomputes. Do not erase draft until confirmed response. |
| Connection drops during send | Keep the exact payload/key in safe outbox; show `لم يتم الإرسال — محفوظ على الجهاز وجارٍ إعادة المحاولة`; automatic/manual retry uses same key. This is resilient-online retry, not an offline accounting engine. |
| Server returns validation/conflict | Keep input and key only if retrying same unchanged request is valid; generate new intent/key after user changes inputs as the mutation protocol requires. Render field/error summary and preserve context. |
| Session expires | Preserve allowed local draft/outbox, clear session data/cache on sign-out/switch, return to login and prompt safe retry after re-authentication. |

## Form test requirements

- Test every shared primitive for label/error linkage, focus, disabled/loading state, raw decimal string preservation, Arabic/Western numeral input, long Arabic labels and 48px target size.
- Test purchase/sale one-line keyboard and touch paths; preview versus server response; per-line unit override; invalid deduction; safe recovery; duplicate-submit/idempotency; draft restore and interrupted retry.
- Test each destructive confirmation for record name, consequence, required reason/cash fate, Esc/click-outside safety and server revalidation.
- Test sensitive forms/routes with direct API role probes. UI absence is never accepted as authorization proof.
- Test virtual keyboard placement at a 320px-wide phone viewport, 200% zoom, desktop Tab/Enter/Escape sequence, Arabic RTL, screen-reader labels/statuses, empty/error/offline/expired-session states before a form is marked `VERIFIED COMPLETE`.
